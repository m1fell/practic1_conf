# Эмулятор UNIX-подобной командной оболочки

Учебная практическая работа на Python. Программа предоставляет консольный интерфейс и виртуальную файловую систему (VFS), состояние которой хранится в памяти.

## Требования

- Python 3.10 или новее
- Git (для коммитов)
- PyYAML из `requirements.txt`

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

На Windows активация окружения обычно выполняется командой `.venv\\Scripts\\activate`.

## Запуск

Интерактивный режим с VFS по умолчанию:

```bash
python main.py
```

Параметры запуска:

```bash
python main.py --vfs vfs_examples/minimal
python main.py --script scripts/start_all.txt
python main.py --config config/config.yaml
python main.py --vfs vfs_examples/minimal --script scripts/start_all.txt --config config/config.yaml
```

Поддерживаемые параметры: `--vfs`, `--script`, `--config`. Если настройка указана в YAML, она имеет приоритет над одноимённым параметром командной строки, как требует задание.

Относительные пути считаются относительно текущей рабочей директории, из которой запущен `main.py`.

## Команды

- `ls [путь]` — показать содержимое каталога.
- `cd [каталог]` — перейти в каталог; без аргумента перейти в корень VFS.
- `whoami` — показать имя пользователя текущей ОС.
- `tac <файл>` — вывести строки файла в обратном порядке.
- `echo [текст ...]` — вывести текст.
- `touch <файл> [файл ...]` — создать пустые виртуальные файлы.
- `vfs-init` — очистить физическую директорию VFS и сбросить виртуальное дерево.
- `exit` — завершить эмулятор.

Парсер раскрывает переменные окружения реальной ОС, например `$HOME`. Файлы, созданные через `touch`, существуют только в памяти и не записываются на диск. Исключение — служебная команда `vfs-init`: по условию она очищает физическую директорию, используемую как источник VFS. Поэтому запускайте её только на тестовой директории проекта.

## Тестирование

Стартовый скрипт эмулятора:

```bash
python main.py --vfs vfs_examples/nested --script scripts/start_all.txt
```

Системные скрипты для проверки аргументов и разных VFS находятся в `scripts/`. Запускайте их из корня проекта:

```bash
bash scripts/test_cli_parameters.sh
bash scripts/test_vfs_variants.sh
bash scripts/test_config_priority.sh
```

Некоторые тесты намеренно используют ошибочные пути и показывают сообщения об ошибках. `test_vfs_variants.sh` запускает `vfs-init` только на тестовых директориях `vfs_examples/`; после такого теста при необходимости восстановите примеры через Git: `git checkout -- vfs_examples`.

## Коммиты по этапам

Рекомендуемый порядок разработки и коммитов:

```bash
git add .
git commit -m "feat: implement REPL prototype"
git commit -am "feat: add command-line configuration"
git commit -am "feat: implement virtual filesystem"
git commit -am "feat: implement shell commands"
git commit -am "feat: add touch command"
```

Важно: эти команды — примеры оформления. Чтобы история Git действительно отражала этапы, коммитьте соответствующие изменения после каждого этапа, а не создавайте все коммиты в самом конце.

## Ограничения учебной реализации

VFS загружает текстовые файлы в память в UTF-8, а символические ссылки пропускает. Изменения, внесённые командами эмулятора, не синхронизируются обратно на диск, кроме очистки физической директории командой `vfs-init`.
